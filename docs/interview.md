「旅行のお店には、たくさんのカードがあります。まず『台北で、4000元まで、まだ買える』カードを集めます。名前から探す係と、似ているものを探す係がいます。2人のカードを合わせて、同じカードを1枚にします。それから、ほしいものに近い順に並べます。」

「一番上のカードは、みんなが見やすいのでよく押されます。でも、よく押されたから一番よいとは限りません。見えやすさも考えます。答えを先に見たテストで100点を取っても、本当に上手か分かりません。だから練習の問題と最後のテストを分けます。」

「この作品のカードとお客さんは作りものです。本当のお店でも役に立つかは、まだ試していません。」

## 日本語：60秒の紹介

「旅行検索を候補検索とランキングに分離したPython作品を実装しました。販売条件を先に確認し、BM25とベクトル検索の結果をRRFでまとめます。PyTorchではpointwise、pairwise、listwiseを比較しました。モデルの選択にはvalidationだけを使い、同じsessionの混入や未来の特徴を検査します。NDCGだけでなくRecall、MRR、長尾slice、信頼区間も出します。クリックには表示順位の偏りがあるため、既知の観測確率を使う合成実験も作りました。現時点では合成データの検証で、実CVRの改善実績ではありません。実務では御社のログ定義とSLOを確認し、小さいA/Bから検証したいです。」

## 繁體中文：面試60秒說明

「我把旅遊搜尋拆成召回、融合、排序和驗證。先確認目的地、預算與可售狀態，再用關鍵字與向量兩條路找候選，透過RRF合併。我用PyTorch比較pointwise、pairwise和listwise，並以時間切分資料，只用訓練資料計算標準化參數，用驗證集選模型。測試會擋住未來特徵和重複查詢，評估除了NDCG，也看Recall、MRR與不同切片。點擊會受曝光位置影響，所以我另外做了已知曝光機率的合成實驗。這份作品驗證的是流程，還不是正式流量的成效。若進團隊，我會先確認log、轉換定義與延遲SLO，再用可回滾的實驗逐步驗證。」

## よく聞かれる質問

| 質問 | 答える要点 |
|---|---|
| なぜ巨大なLLMを最初から使わない？ | 基準と正解集合がないと費用に見合う改善を測れない。候補Recallを先に確認する |
| なぜ3つのloss？ | 1商品を判定、2商品を比較、リスト全体を比較する違いを実装で説明する。最高値だけを選んで自慢しない |
| NDCGが上がれば予約も増える？ | 関連度と予約は別。価格・在庫・季節がある。実A/Bの主指標とguardrailで確認する |
| 未クリックは負例？ | 見られていない可能性がある。exposureと位置、観測窓を確認する |
| Starsが多いから正しい？ | 人気を示すだけ。環境固定、再実行、データ定義、公式checkpointと評価設定が別途必要 |
| なぜMRR=1でも完成ではない？ | 最初の関連商品が常に1位になる簡単な合成課題。下位の並びや漏れを測れない |
| 本番の経験がある？ | この作品を本番経験へ言い換えない。実際に経験した範囲と本作品で学んだ範囲を分ける |
| 次に何をする？ | 正式な利用権のあるjudgmentとログを確保し、事前学習encoder、filter付き検索、同一候補ablation、負荷試験へ進む |

## 実演の順序（約5分）

1. `python -m unittest discover -s tests -v`で不正入力・漏洩・指標の検査を見せる。
2. `python -m travel_rank.demo`でvalidation選択とheld-out結果を開く。
3. `reports/demo.json`の合成データ表示、split、MRR飽和、IPS仮定を説明する。
4. `python -m travel_rank.api`で予算を0にし、空結果が正しく返ることを見せる。
5. 本番で未実装の部分を自分から示し、検証の順番を話す。
